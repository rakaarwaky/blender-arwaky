LINTER INTEGRATION
==================

Use lint-arwaky-cli to analyze the Python workspace.

Full analysis, discovering modules and running all linters:

```
lint-arwaky-cli scan <path>
```

Targeted analysis, running one linter independently:

```
lint-arwaky-cli <quality|import|naming|role|orphan|external> <path>
```

Common flags:

```
--format <FORMAT>
--filter <CODE
-o, --output-dir <DIR>
--member <name>
```

Meaning:

- <path> defaults to current directory.
- --filter filters violations by AES rule ID, example: AES201.
- -o, --output-dir saves report files.
- --member targets a single workspace member by module name

NO MONITORING ONLY
==================

**STRICT RULE: Every cycle MUST implement a fix. Verification-only passes are forbidden.**

- Do NOT run tests, linters, or scans without also fixing at least one violation from TODO.md.
- Do NOT report "886 tests passing" as progress — that is not progress.
- Do NOT defer violations. Each cycle must close at least one item from TODO.md.
- If you cannot find a concrete fix, the cycle FAILED. Record failure in AUDIT.md and move to the next violation.

WORK CYCLE
==========

1. Discover

---

Read TODO.md, AUDIT.md, HEARTBEAT.md. Pick the FIRST unresolved violation or action item. Do NOT scan for new gaps — work what is already listed.

2. Select

---

Confirm the selected violation is actionable (has a file path, rule code, and clear remediation step). If ambiguous, resolve in this cycle — do not defer to QUESTIONS.md unless truly blocked.

3. Spec Check

---

Confirm the fix satisfies Core Rules and Mandatory Code Structure.

4. Implement

---

Apply the fix NOW. Write real code changes:
- Remove bypass comments and fix the root cause (not add `type: ignore`)
- Add missing exports to `__init__.py`
- Rename files to match contract naming conventions
- Delete orphan contracts if deprecated
- Fix actual bugs, not lint noise

5. Verify

---

Run tests and linters AFTER making changes to confirm the fix worked and nothing broke.

6. Audit

---

Skeptically review the change for hidden defects. Did the fix actually resolve the violation, or just suppress it?

7. Harden

---

Improve the changed area. Check for similar violations in the same file/module and fix those too (batch remediation).

8. Record

---

Update Loop State Files concisely:
- DONE.md: what was fixed with file paths and rule codes
- TODO.md: remove completed items, promote next priority
- HEARTBEAT.md: log cycle number, what was fixed, violations closed count
- STATE.md: update readiness scores if module changed

9. Next

---

Begin the next cycle immediately. Pick the next violation from TODO.md.

Any deviation from Mandatory Code Structure is a violation.

Remediation:

- Record violation in .agents/loop/AUDIT.md.
- Add remediation task to .agents/loop/TODO.md.

If ambiguous:

- Record question in .agents/loop/QUESTIONS.md.
- Record safe assumption in .agents/loop/ASSUMPTIONS.md.
- Choose smallest safe interpretation.
